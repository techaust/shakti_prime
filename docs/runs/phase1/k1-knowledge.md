- **10, design as built: one page per delivery.** `maskNextPdfPage` (`apps/web/src/workers/files/mask-pdf-pages.ts`) opens the upload's PDF, counts the pages (more than 12, or a PDF that will not open, is refused as before), reads which pages are kept, draws the next one only, masks it and keeps it. The progress is in the file store, beside the upload, under `<upload>-checked/`: for each page `p0001.jpg` (the masked picture), then `p0001.json` (its size in points and the regions covered); a page counts as kept once its record exists. The store keeps the first bytes written under a key (S3 `IfNoneMatch`), so two deliveries on one page cannot both write it; a picture left by a delivery that died before its record is deleted and written again. The delivery then calls the new command `files.file.continue_check` (`files.process`, the file's company; a no-op unless the file is a vault upload in `scanned` or `not_scanned`), which emits `files.file.uploaded` again through the outbox with `payload.maskedPages` (the pages kept); `EVENT_WORKERS` delivers it to the same worker, so no new route. A delivery whose `maskedPages` is below the pages already kept is stale and does nothing, so a redelivered page is never masked twice; if the command fails the page record is deleted so the retry masks that page again. A claim `filecheck:<fileId>` in the key-value store (90 seconds, the route stops at 60) keeps two deliveries on one file from working at once; one that finds it taken answers `conflict` (`event_in_progress`) and is delivered again. When the last page is kept the same delivery assembles the masked PDF (`jpegsToPdf`), stores it, records `masked`, then deletes the upload and the per-page parts (the parts are also deleted on every refusal and on each later delivery of a finished file, as the upload's own bytes are). Deadlines per delivery: a page not drawn within 15 seconds of the delivery's start, or still being masked 45 seconds in, refuses the file as `file_pdf_page_too_dense` (a new reason, with a plain sentence for the uploader and for the vault list: `knowledge_pdf_page_too_dense`, a new vault reason in the check constraint, contracts and copy); a page that runs past 45 seconds also closes the masking step (`discardVaultMasker`) so the busy engine does not hold up the next check, and the raw upload is deleted. `KNOWLEDGE_PDF_MAX_PAGES` stays 12; photos stay one delivery.
