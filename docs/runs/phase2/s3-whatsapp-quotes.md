**Decisions the brief did not settle**
1. The permission is spelled `sales.quote.accept.remote`, not `sales.quote.accept_remote`: the catalogue's rule (`permissions.test.ts`, `^[a-z]+(\.[a-z]+){1,3}$`) refuses an underscore, and a four-part key has its precedent in `knowledge.vault.read.staff`. The command keeps the name `sales.quote.accept_remote` (command names take underscores). The design's §4 and §7.1 now name the key as built. If the lead prefers the brief's spelling, the catalogue test's rule has to change instead, which I did not do.
2. "Factor the order building, never copy it": the copy of an accepted quote into its order is one SQL function, `app.order_from_quote()`, run as its caller. The person's acceptance moved from Drizzle inserts to it (still under its own order policies; the orders, quotes and sales-integrity suites pass unchanged) and the platform's definer runs the same function. The machine moves, numbering, audit and events are one module, `sales/quote-acceptance.ts`, used by both commands.
3. The quote machine's `withdraw` is `system: true`, so the platform's acceptance withdraws the lead's other quotes through the machine, as a person's does.
4. A quote sent by WhatsApp goes through the milestone registry, not `messaging.message.queue`: `quote_sent` is one of the eight milestones, and a person cannot run a platform command, so `sales.quote.send` checks and emits `sales.quote.sent` naming the chat, and the platform's subscriber (step 5) runs `messaging.milestone.send` for `quote_sent`, which records it once per quote, holds it while its template is not approved and attaches the PDF. `messaging.message.queue` stays W1's welcome and STOP confirmation.
5. A milestone's body values (number, total in rupees, valid-until date) are made by the worker in `apps/web` with the print formatters, since `packages/domain` has no rupee formatter and must not import the web app's; the definer checks their count against the template and the command masks them. A template mapped to a milestone must take exactly `WHATSAPP_MILESTONE_VALUES` (quote number, grand total, valid until; order number, grand total).
6. Only `queued` and `held` are recorded per subject; `no_chat`, `opted_out`, `no_consent`, `not_mapped` and `not_due` are answered, not recorded, so a later event can still send. A held milestone is never sent later.
7. Consent for a WhatsApp quote or milestone: a WhatsApp consent, not withdrawn, of a contact of the customer who holds the chat's number. The chat: the one named when it is the customer's, else the customer's chat in the company with the latest message from them.
8. The quote's second button is "Talk to us" (`t`), which step 5 answers by handing the chat to people; the brief names two buttons but not the second. The messaging worker will compute the tokens when it sends, so no token is stored.
9. STATUS lists the five newest quotes (sent, accepted, expired) and the five newest orders of the chat's customer in the company.
10. Settings maps only the two milestones that have an event in Phase 2 (`WHATSAPP_LIVE_MILESTONES`); the other six are in the table's check and the contracts for later phases.
