# Auditor 5: tests, CI/DevOps and observability (main at 23f78a5)

## Score
**7 / 10.** The test discipline is unusually strong where it is structural: the registry test ties every exported command to the registry, the agent refusal sweep reads the registry so a new restricted command is covered the day it is added, the role × company matrix fails when an `ENTITY_TABLES` table has no rule or fixture row (a live comparison of the 77 public tables with the testing lists found none missing), the pure cores (tax, sizing with a property test, credit, TRAI hours and DND, state machines through per-machine fixtures) have boundary tests, and time-of-day is injected everywhere I looked (the calls tests take `now`, the journeys use the test-clock cookie). Every GitHub Action is pinned by SHA, every workflow has a least-privilege `permissions` block, CI uses no secret, and the merge rule refuses forks, drafts, `hold`, a newer head and Dependabot majors (checked with `jq` against sample payloads). What keeps the score down is the gap between "CI is green" and "main is safe", and the gap between "something failed" and "someone is told". (1) The merge-on-green workflow merges a pull request tested against an older `main`, and the pull request under test can rewrite the CI that gates it. (2) Only two alert names ever reach Sentry: handled failures (every server action's `internal`, every scheduled job's 500, a schedule refused for its signature) go only to the log. Nothing outside the app watches `/health/ready`. (3) The real OCR masking of Aadhaar digits never runs in CI. (4) About ten commands lack the denied or wrong-company case that AGENTS §5 requires. **To reach 10:** re-test or refuse a pull request whose tested base is behind `main`, and hold any pull request that touches `.github/` or the test configuration for the owner; report `error`-level lines and job failure streaks to Sentry; add an external monitor or Sentry cron check-ins per schedule; run the OCR case in CI with a cached model; fill the per-command test gaps; and add a `cooldown` to Dependabot.

## Checked and sound
- **Registry and sweeps.** `registry.test.ts` checks that every exported command is registered once under its own name. `agent-refusals.test.ts` derives the restricted, people-only and customer-write sets from the registry and requires an input for each. `event-emitters.test.ts` is registry-driven.
- **Tables.** All 77 public tables in the live database (migrated through 0129, 130 rows in the journal) appear in the testing lists. `role-entity-matrix.test.ts:349-383` fails when an `ENTITY_TABLES` table has no matrix rule or no fixture row per company.
- **Pure functions.** TRAI hours have second-level boundaries (`dial-policy.test.ts:31-45`); DND and DLT series are covered; credit check has 14 cases; tax has 13 plus a golden set (awaiting the CA, excluded); sizing has 11 files including a property test. State machines go through per-machine fixtures (`machines.test.ts:255`) plus guard cases.
- **Clocks.** The calls and call-queue tests inject `now`. The journeys use the test-clock cookie (`e2e/support/clock.ts`), which only a local runtime honours. The literal dates in database tests are either past ranges or 2031 future fixtures. No `.only`, and no skipped test except platform- or project-scoped ones and OCR (OPS-5).
- **Shared state.** The database suites run `fileParallelism: false` (db, domain and web) and `test:security --concurrency=1`. CI starts each from a fresh service database.
- **Workflows.** Every `uses:` is pinned by commit SHA. `permissions` is read-only at workflow level, `{}` plus the job's write scopes in automerge. No `pull_request_target` anywhere. CI reads no secret, so fork PRs expose nothing. Automerge checks out no code and passes event values through `env`. The rule refuses forks, drafts, non-`main` bases, `hold`, a head newer than the tested one (plus `--match-head-commit`), unknown authors and Dependabot majors: a group's title, a single bump's major and a SHA-titled actions bump were each tested with `jq`. Only `conclusion == success` on `pull_request` merges. CI's concurrency cancels superseded PR runs only.
- **Migrate workflow.** It refuses a non-`main` ref, a missing secret and a URL for the wrong project. `rotate_passwords` maps to `--rotate-passwords`, which `migrate.ts:168` reads, and `db:verify` runs after either migrate step. The migrator holds an advisory lock with `lock_timeout = 10s`, as incidents §3 says.
- **Turbo strict env.** Every variable the security suite reads is listed (vendor harness keys are injected per test). `build` lists the `NEXT_PUBLIC_*`, `VERCEL_*`, Sentry and Turnstile variables `next.config.ts` reads. CI's `build` job runs with no `.env`. Playwright loads the root `.env` itself, so `test:e2e`'s shorter list does not starve the app.
- **Production guard.** `productionConfigProblems()` matches DEPLOY §1 step 12's list exactly and refuses test Turnstile keys, short or published secrets, non-https URLs, `FIELD_ENCRYPTION_KEY`, `AI_TRANSPORT` and a non-SES production mailer. The field cipher fails closed on a hosted runtime without KMS.
- **Logging and Sentry.** Logs are JSON lines through `redact()`, which drops secret-named keys, identity numbers, and query parameters and text. `onRequestError` logs one redacted line with the reference and request id. Sentry has `sendDefaultPii: false` and scrubs events, transactions and breadcrumbs. The outbox streak counter lives in the shared key-value store, not in instance memory.
- **Health.** Liveness touches nothing. Readiness checks the database, auth database, key-value round trip, config and outbox age, is rate-limited, and names the down check only in the log.
- **Incidents runbook.** Checked against the code: 10 tries (`OUTBOX_MAX_ATTEMPTS`), the five-minute outbox check, ten-minute file waits, the alert names, and the migrator's single transaction under an advisory lock.
- **Dependencies.** Dependabot keeps Playwright and the TypeScript, ESLint and `@types/node` majors out, and groups minor and patch updates. `pnpm audit` runs in CI and weekly. `allowBuilds` limits install scripts, and every audit exception has its reason.
