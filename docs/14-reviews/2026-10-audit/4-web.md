# Auditor 4: web app, UX, accessibility and copy (WEB)

Scope: `apps/web`, `packages/ui`, `packages/tokens`, `tools/copy-lint` at `main` 23f78a5. Read-only. Nothing heavy was run except the copy lint (clean). Contrast ratios were computed from the generated `packages/tokens/src/tokens.css` with the WCAG formula. The Linux phone baselines were inspected by eye.

## Score
**7.5 / 10.** The web layer is disciplined. Every one of the 40 `(bos)` pages calls `screenAccess()`, 39 of them with `navRequires()`, and profile and notifications are open to everyone signed in. Every action goes through `executeCommand()`/`executeQuery()` and answers an `ActionResult` with a catalogue key and a reference; nothing throws to a screen. Nothing reads a secret or opens a connection at import time. Colours come only from tokens, with the source-rule tests enforcing it. Print templates are forced light. There are three Playwright projects (light, dark, 400 px) with axe checks on almost every screen, typed message keys, and a copy lint that is clean.

What keeps it from 10:
- About 168 kB of the catalogue is shipped in the payload of every page, the public sign-in page included, and the JavaScript budget does not measure it. This undoes AUDIT L12 in practice.
- Server errors that belong to a field are silent for screen-reader users.
- The root error screen's "Try again" cannot recover from the outage it is shown for.
- Raw tables stay tables on phones, against §5.
- A few smaller defects: shared idempotency keys across rows, one contrast pair below AA, an expired-session path, and a few copy and test gaps.

Fixing WEB-1 to WEB-4 and adding the missing contrast pairs to the test would make this a 9. Closing the rest would make it a 10.

## Checked and sound
- **Page guards:** all 40 `(bos)` pages call `screenAccess()` (39 with `navRequires()` or `BUILDER_REQUIRES`; profile and notifications open to anyone signed in). `screenTitle()` gives no screen name to a caller who may not open it. `session-gate.test.ts` holds the proxy prefixes in step with the folders.
- **Database and secret access:** server actions reach the database only through `executeCommand`/`executeQuery`, or helpers that call them (`observability/integration-health.ts`). The only `@shakti/db` imports in `apps/web/src` are auth, readiness and the workers. `process.env` is read only at render time (the public Turnstile site key), never at module scope. No module-level connection exists.
- **Error handling:**
  - Actions never throw; `toResult`/`actionFailure` map errors to `errors.*` with a reference for unexpected failures.
  - `settle()` turns a lost answer into the `internal` sentence.
  - `errors-catalogue.test.ts` covers error codes, runner reasons, `constraintReasons`, machine reasons, auth reasons and every `reason: '…'` literal. Variable reasons I traced (`uploadLimitProblem`, `ImportFileReason`, `ORDER_REASONS`, inbox and knowledge caps, `idempotency_mismatch`) all have sentences.
  - No `.message` or stack reaches a response or a screen.
  - `(bos)/error.tsx` keeps the shell and uses `retry`. Root `not-found.tsx` and `global-error.tsx` exist, and `global-error` carries only its own copy.
  - A detail page with a bad id or a refused read answers not-found.
- **Forms:** one idempotency key per rendered form (`useCommand`), sent as the second argument and replayed after a lost answer. Pending buttons stay focusable and ignore a second press. The public forms move focus to the first invalid field and announce repeated errors again. Native validation text comes from the catalogue. The email survives a failed sign-in (M52). Pop-up-safe file opening (`use-open-file.ts`). The palette search ignores out-of-order answers.
- **Theming:**
  - No hard-coded colours outside the QR code's light background (WEB-9) and the OCR mask SVG.
  - `style-rules.test.ts` and `source-rules.test.ts` enforce tokens.
  - System/Light/Dark through `next-themes`, with a cookie for the first paint and high contrast.
  - Print CSS is `color-scheme: light` with light tokens only (tested).
  - Every pair in `CONTRAST_PAIRS` passes in all four variants. The focus ring is 3.8–7.1:1 on `bg`, `surface` and `surface-2`, and danger buttons are 5.3:1 (light) and 6.0:1 (dark).
- **Accessibility:**
  - Skip link, `header`/`aside`/`main` landmarks, one `h1` per page, and a title per page (M53).
  - Global `:focus-visible` ring; `outline-none` only on programmatic-focus headings, containers and highlighted menu items.
  - Every icon-only button has an `aria-label`.
  - `DataGrid` has a caption, `scope`, `aria-sort`, a live count and phone cards.
  - Scrolling tables are focusable or hold links.
  - Radix dialogs with `returnFocusTo`.
  - Axe runs in about 180 calls across 26 specs in light, dark and 400 px, including dialogs.
- **Copy:**
  - `pnpm copy-lint` is clean.
  - `react/jsx-no-literals` covers JSX text. A scan of literal `aria-label`/`placeholder`/`title`/`alt` props and toast strings found none.
  - No Devanagari in the source. No Hinglish outside the (not yet written) caller scripts.
  - Message keys are typed through `AppConfig`. Button keys used in `<Button>` fall under the 24-character rule.
  - No banned or vendor words in the catalogue except the accepted product terms (CSV, XLSX, Tally, autonomy).
- **Performance:**
  - Every staff route measured in `js-budget.json` sits within 5 % of its budget except the known `/settings/profile`. Seven routes use the 250 kB default, which TESTING §5 allows.
  - The palette, the menus and the toasts load late.
  - Client components import only types from `@shakti/contracts` (the lint rule holds) and nothing from `@shakti/db` or `@shakti/domain`.
  - The bell and Vault polls stop while the tab is hidden.

## Not checked
- `pnpm build` with no `.env` and `pnpm --filter web js-budget` were not run (heavy; the budget figures are the recorded ones).
- Journeys and axe were not re-run.
- The framework's response to a proxy-redirected server action (WEB-7) and Better Auth's refresh during an action (WEB-8) were read, not reproduced.
- The phone top bar's width with all five controls was judged from baselines only.
