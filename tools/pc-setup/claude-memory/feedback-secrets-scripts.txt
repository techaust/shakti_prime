On 06-10-2026 the owner pasted terminal output containing dev passwords and the auth secret into chat while following hand-built `export` lines; hand-assembled connection strings then failed twice. Scripts in `D:/shakti-wt/` that prompt with hidden input (`Read-Host -AsSecureString`), build the URL, test it against Supabase and store it (`gh secret set`, or the clipboard for Vercel) worked first time.

**Why:** the owner is not a shell user; their new terminal windows do not see the user PATH (pnpm, node not found), Git Bash bracketed paste mangles lines, and anything pasted to chat is exposed and must be rotated.
**How to apply:** for any owner step involving a secret, write a small `.ps1` that calls `C:\Program Files\nodejs\node.exe`, `C:\Program Files\GitHub CLI\gh.exe` and repo tools by full path, prompts hidden, verifies before saving, prints only a RESULT line; run as `powershell -ExecutionPolicy Bypass -File <path>`. Tell the owner to copy only RESULT/error lines into chat. If a secret is ever pasted, rotate it (DEPLOY §5; BETTER_AUTH_SECRET only before authenticators exist, else SECURITY §10).
